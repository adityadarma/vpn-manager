---
title: Install a VPN Node
description: Install OpenVPN or WireGuard and the Agent on a node host.
---

## Prerequisites and security

The node must be a Linux host with `root` or `sudo`, Docker Engine, Docker Compose v2, and connectivity to the Manager. The Agent uses host networking plus `NET_ADMIN` and `NET_RAW` capabilities; use a dedicated host or restrict its administrative access.

The script can install OpenVPN or WireGuard. Ensure UDP `1194` is reachable for OpenVPN or UDP `51820` for WireGuard unless the node port is configured differently. Host firewalls and cloud security groups must allow the selected port.

## Auto-registration

Get `NODE_REGISTRATION_KEY` and `VPN_TOKEN` from the Manager installation. Run this command on the node, replacing the URL with a Manager URL that the node can reach.

```bash
curl -fsSL https://raw.githubusercontent.com/adityadarma/vpn-manager/main/scripts/install-agent.sh | sudo bash -s -- \
  MANAGER_URL=https://vpn.example.com \
  VPN_TOKEN=replace-with-vpn-token \
  REG_KEY=replace-with-registration-key \
  VPN_TYPE=openvpn
```

For WireGuard, use `VPN_TYPE=wireguard`. The optional `VPN_SUBNET=10.8.1.0/24` requests a specific subnet; without it, the Manager can allocate a network. Avoid subnets that overlap the LAN, Docker networks, or other nodes.

The script creates `/opt/vpn-agent/.env`, registers the node at `/api/v1/nodes/register`, receives the Node ID and secret token, then starts the `vpn-agent` container. Once credentials exist, rerunning the script updates the image without overwriting the registered Agent configuration.

### Release channels

The command above installs the stable `latest` channel. To install the moving beta channel for testing, add `CHANNEL=beta`:

```bash
curl -fsSL https://raw.githubusercontent.com/adityadarma/vpn-manager/main/scripts/install-agent.sh | sudo bash -s -- \
  CHANNEL=beta \
  MANAGER_URL=https://vpn.example.com \
  VPN_TOKEN=replace-with-vpn-token \
  REG_KEY=replace-with-registration-key \
  VPN_TYPE=openvpn
```

The installer writes `IMAGE_VERSION=beta` to `/opt/vpn-agent/.env`, so later installer updates stay on beta. The release workflow publishes `ghcr.io/adityadarma/vpn-agent:beta` whenever a beta prerelease tag (such as `v1.1.8-beta.1`) is pushed. Beta is intended for testing only; omit `CHANNEL=beta` for stable production deployments.

To switch an existing Agent back to the stable channel, rerun the installer with the same registration settings and `CHANNEL=latest`. The installer preserves the Agent ID and secret token while updating `IMAGE_VERSION` in `/opt/vpn-agent/.env`.

The base `/opt/vpn-agent/docker-compose.yml` remains generic. The installer writes host-specific mounts to `/opt/vpn-agent/docker-compose.override.yml`, which Docker Compose loads automatically:

- OpenVPN: `/etc/openvpn`, `/run/openvpn`, and read-only `/var/log/openvpn`.
- WireGuard: `/etc/wireguard`.
- firewalld: `/run/dbus/system_bus_socket` so `firewall-cmd` in the Agent can communicate with the host daemon.

## Firewall and forwarding

The script detects the active firewall and offers `iptables`, `nftables`, `ufw`, `firewalld`, or `none`. Keep the firewall already active on the host unless you understand the consequences of conflicting rules.

The script enables `net.ipv4.ip_forward=1`, creates forwarding rules, and configures NAT for non-LAN traffic. For the detected LAN, it attempts to preserve the VPN client source address. With `none`, the administrator must configure forwarding, NAT, and port rules manually.

## Manual registration

Use this when a node already exists and has a Node ID and secret token. Create `/opt/vpn-agent/.env`:

```dotenv
AGENT_MANAGER_URL=https://vpn.example.com
VPN_TOKEN=replace-with-vpn-token
AGENT_NODE_ID=replace-with-node-id
AGENT_SECRET_TOKEN=replace-with-agent-secret
VPN_TYPE=openvpn
FIREWALL_ENGINE=auto
AGENT_POLL_INTERVAL_MS=5000
AGENT_HEARTBEAT_INTERVAL_MS=30000
```

Copy `docker-compose.agent.yml` to `/opt/vpn-agent/docker-compose.yml`, then create `/opt/vpn-agent/docker-compose.override.yml` for the host-specific mounts above. When `FIREWALL_ENGINE=firewalld`, also mount `/run/dbus/system_bus_socket` into the Agent. Run `docker compose up -d` from that directory.

## Verify the node

```bash
docker logs -f vpn-agent
systemctl status openvpn-server@server
systemctl status wg-quick@wg0
```

OpenVPN uses the `/run/openvpn/server.sock` Unix socket, not a TCP management port. Check Nodes in the dashboard: the Agent sends a heartbeat every 30 seconds by default and the node goes offline after two minutes without one.

## Uninstall

Run this on the node host:

```bash
curl -fsSL https://raw.githubusercontent.com/adityadarma/vpn-manager/main/scripts/uninstall-agent.sh | sudo bash
```

Or, if you already have the repository checked out:

```bash
sudo bash scripts/uninstall-agent.sh
```

The script reads `/opt/vpn-agent/.env` to detect which engine (`OpenVPN` or `WireGuard`) and firewall engine were configured at install time, then:

1. Notifies the Manager to delete this node (`DELETE /api/v1/nodes/me`), so it disappears from the dashboard instead of showing as permanently offline. This step is best-effort — the uninstall continues even if the Manager is unreachable.
2. Stops and removes the `vpn-agent` and profile-managed `vpn-coredns` containers, plus the `managed-dns` Docker volume.
3. Offers to remove all local Agent image tags, including `latest`, `beta`, and semantic version tags.
4. Stops the VPN engine (`openvpn-server@server` or `wg-quick@wg0`) and its NAT/forwarding systemd units.
5. Removes only the firewall rules tagged as created by VPN Manager (iptables policy chains, the `nftables` tables it created, `ufw` rules commented `vpn-manager`, or the `firewalld` direct rules/rich rules it added) — it does not touch unrelated firewall configuration.
6. Uninstalls the `openvpn`/`easy-rsa` or `wireguard-tools` packages and removes `/etc/openvpn`, `/etc/wireguard`, and `/opt/vpn-agent`.
7. Reverts the `net.ipv4.ip_forward=1` sysctl setting only if it was added by VPN Manager (marked with a comment in `/etc/sysctl.conf`); a pre-existing setting is left untouched.

If `/opt/vpn-agent/.env` is missing (for example, the Agent directory was already deleted manually), the script cannot detect which engine was installed and offers a force-purge mode instead — typing `PURGE` removes both OpenVPN and WireGuard and attempts firewall cleanup for every supported engine. Use this only when you are certain no other VPN setup shares the host.

This does not delete client certificates or WireGuard peer keys stored in the Manager's database — those remain associated with the deleted node's history unless removed separately.
